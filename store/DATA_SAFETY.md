# Data safety worksheet

Draft for owner review. This is evidence for answering the Console form, not a submitted declaration.

| Flow | Current implementation | Declaration decision to review |
| --- | --- | --- |
| Connection name, server, username and password | Runtime input; optionally encrypted on-device with Android Keystore; removed locally on sign out; backup disabled | Authentication data leaves the device to the user-selected provider. Evaluate the applicable collection, sharing, user-initiated transfer and service-provider definitions; do not assume “no collection”. |
| Provider API requests | HTTP or HTTPS according to the supplied base address; Xtream credentials are query parameters sent to that provider | Explain authentication purpose and identify the recipient categories. HTTP requests are unencrypted. Provider server retention is controlled by the provider. |
| Video and artwork requests | Device IP and normal network headers go to provider/CDN/artwork hosts. Stream URLs may carry credentials. HTTP and HTTPS delivery work automatically | HTTP support means a blanket “all user data encrypted in transit” answer is unsafe. Redirects may use other hosts; disclose these flows. |
| Catalog and artwork | Catalog in memory; one private artwork loader/cache limited to 50 MiB disk and 12 MiB memory | Cache persists temporarily on-device. Daily maintenance prunes old app temp files and clears the image disk cache approximately weekly while backgrounded. |
| Offline downloads | User-initiated direct media downloads in private app storage or a chosen local document tree; account/classification/local-location index; Keystore-encrypted pending request addresses | Pending addresses are removed on completion/removal/logout. Completed media stays until removed, outside cache cleanup. Logout hides its library. Shared-folder files can be opened by other apps with access and can remain after uninstall. Background transfer notifications are local, with no developer push backend. |
| Viewing activity | Account-scoped SQLite history stores content/episode IDs, titles, extensions and last-playback-start times; progress stores positions, optional durations, completion/watched flags and last-played times | Movie/episode history lasts 180 days and live history 10 days. Watched status and resume points stay until explicitly cleared. Logout hides records; cache cleanup preserves progress. Settings clears the connected account's viewing records after confirmation; Android Clear storage/uninstall removes all local records. No credentials or playback/artwork URLs enter these tables and no developer analytics backend receives them. Provider logs can still reveal selections. |
| Parental settings | Salted password verifier and category/adult restrictions persist locally; adult blocking defaults to enabled | No plaintext parental password or panel access grant is persisted. Reset removes the password and every account's custom locks while restoring adult blocking. These settings survive logout/cache cleanup. |
| Subscription reminders and preferences | Device-local language/settings and account/expiry-specific reminder acknowledgements | Reminders use the provider's sign-in expiry snapshot while browsing; no background/system notifications or developer-operated push service. Acknowledgements remain outside caches. |
| Advertising, analytics, crash-upload SDKs | None configured | Recheck resolved dependencies and final release. Adding any SDK requires this worksheet and policy to be updated. |

The developer currently operates no account or streaming backend for this app. The app does not create IPTV accounts; provider account deletion must be requested from the provider. Signing out removes the remembered connection locally, not the provider's account or locally retained viewing records. Clearing Android app storage removes the app's local data and cache. See the [security policy](../SECURITY.md) and [storage behavior](../docs/CACHE_AND_PLAYBACK.md) when reviewing the final binary.

Before answering Console, review its current [Data safety definitions](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en), finalize the publisher's practices, and consider every off-device transfer. The app does not request broad storage/media-library, camera, microphone, location or contacts permissions. Selected folders use Android's user-granted document-tree access. Internet, network-state and foreground data-sync permissions support downloads; WorkManager may merge background scheduling/wake-lock permissions.
